# Automation Loop 脚手架

> **触发时机**：用户提到「写 loop / 新模块接入自动化 / 长任务自驱 / 让 agent 自己跑」等。
> **产出**：一份填好的 loop 文档 + 一句话启动指令。
>
> **本 skill 只负责**：问用户收集要素 + 生成 loop 文档 + 输出启动指令，然后结束。
> **执行 loop 是接收启动指令的 Agent 的事**——本 skill 不亲自执行。

---

## Loop 解剖（5 零件 + 1 记忆）

一个可自驱的 loop 由五部分组成，外加一个贯穿的记忆文件：

1. **任务清单**——拆好的、带验收判据的可勾选任务
2. **执行器（Writer）**——干活并落盘
3. **验证器（Verifier）**——独立质检，与 Writer 分离
4. **预算与终止条件**——最大轮数、最大耗时、重试上限
5. **进度输出**——看板/日志，让人类随时可查
6. **记忆文件**——贯穿全程的 loop 文档本身，Agent 每轮从它恢复上下文

## 8 步问答（核心：用 AskUserQuestion 批量问，一次 4 个）

### Step 1 — 项目基本信息（必答）

项目类型（Web 前端 / 后端 API / CLI 工具 / 设备固件 / 其他）；验收用例来源（Excel 导出 / Markdown 人工整理 / 无——Agent 扫代码生成最小 ad-hoc 清单）；运行环境（本地 dev + 真环境 / 纯软件 / CI）；**用户在 loop 期间是否全程离开**（全程离开 = Agent 按实战策略自决；偶尔回来看 = 进度持续落盘）。

### Step 2 — 物理与授权约束

目标资源情况（真环境全套 / 仅基础 / 无真环境）；**跨模块改动授权**（允许加埋点与测试、仅允许加标记、全部禁止）；**commit / push 授权**（全程不 commit 不 push 最后统一审【推荐】/ 每轮自动 commit 不 push / 可 commit + push【激进】）；**失败重试上限**（Writer + Verifier 各 3 次【推荐】/ 各 1 次快失败 / 无上限仅限复杂调试）。

### Step 3 — 终止条件

覆盖率或完成度目标（≥50% 默认 / 更激进 / 保守快交付）；最大轮数（5 轮默认 / 3 轮快迭代 / 10 轮充分迭代）；最大总耗时（8 小时默认 / 4 小时 / 无上限）；**Verifier 是否与 Writer 分离**（独立质检 agent 推荐 / 同模型换 prompt / Writer 自检不推荐——容易过度自信）。

### Step 4 — 路径与文件

基于前 3 步答案**主动推断**默认路径（源码目录、用例表、配置文件），用户只需确认或粘贴修正。用户没提供用例来源时，用一次 AskUserQuestion 让其补全。

### Step 5 — 优先级分层

- **P1（先做）**：核心路径的最小可用集
- **P2（看时间做）**：增强与边界场景
- **P3（明确不做，标 TODO）**：高成本低频场景
- **硬约束（绝对不做）**：默认含「不 push」「不做破坏性操作」

### Step 6 — 知识引用（固化必读）

启动 loop 的 Agent 必读哪些知识文件：项目 conventions + 实战经验（默认）/ 仅 conventions / 另加自定义知识库（用户填路径）。

### Step 7 — 启动前回放

输出一份 markdown 回放（不用 AskUserQuestion）：项目 / 用例来源 / 环境 / 授权 / 预算 / 覆盖目标 / 轮数 / Verifier / P1P2P3 / 硬约束 / 必读清单——**等用户回复「OK」或「修改 XXX」**。

### Step 8 — 生成 loop 文档 + 启动指令

用户确认后：

1. 生成 `docs/<name>-automation-loop.md`：复制 loop 模板，把全部占位符按答案填好
2. 输出一行**启动指令**给用户，例如：

   ```
   按 docs/<name>-automation-loop.md 执行自动化接入。
   - 用例来源：<path>
   - 目标目录：<path>
   - 硬约束：<用户选的硬约束>
   进入自驱循环，按实战策略自决，跑完输出验收单。
   ```

用户把启动指令交给任意 Agent 即可自驱执行。

## 注意事项

- **本 skill 不亲自执行 loop**——只负责收集要素与生成文档，生成完即结束
- 8 步合并为 2~3 次 AskUserQuestion 批量问，全程用户交互不超过 3 次
- 大部分问题给「实战默认」选项，用户不知道选什么就引导选默认
- 文档默认放 `docs/<name>-automation-loop.md`，用户指定则从之

## 实战提炼的经验（写进 loop 文档的默认策略）

- **Writer 与 Verifier 必须分离**——同一个上下文自检容易过度自信
- **预算纪律**：重试上限、轮数、耗时三重封顶，防死循环烧钱
- **失败语义显式**：每个任务的失败分支提前定义（重试/跳过+标记/终止+报告），失败信息贯通到最终验收单
- **进度落盘**：每轮结束把状态写回 loop 文档，任何时点中断都能从记忆文件恢复
