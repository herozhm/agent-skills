# Change Summary

## 目标

只解决一件事：基于真实 git 提交，输出**主题驱动**的、人类可读的「新增功能 / 修复 bug / 版本与发布」三段式编号清单。

**核心原则**：拒绝逐条搬运 commit message。必须按主题归并、按重要度排序，让阅读者一眼看到这段时间「做了什么、修了什么、发了什么」。

## 何时使用

- 整理 / 列出 / 汇总某段时间的「功能」与「bug」
- 给某个仓库 / 模块 / 子系统做改动小结
- 「今天本人提交了多少功能 / 修了什么」
- 准备 release notes / changelog / 周报 / 月报 / 复盘某条分支

**不适用**：单 commit 的描述、commit message 生成、stat 数字汇总、按两个版本号对比出提测说明（那是 release-changelog 的事）。

## 工作流

### 1. 同步最新代码

```bash
git pull --rebase --quiet
git log -1 --format='HEAD: %h %ai %s'
```

不要在本地未同步的情况下做汇总。远端不可达时明确告知用户基于本地状态汇总。

### 2. 解析输入

- **时间范围**：「X 月 X 日到现在」→ 换算成 `--since/--until`；「今天/本周/本月」按 date 命令换算；没说 → 默认今天 00:00 至今。相对时间先转绝对日期，避免歧义
- **范围过滤**：用户给的模块 / 目录 / 子系统关键字 → 转成 path 过滤或 commit subject 的 grep 模式（含模块前缀约定时一并匹配）
- **作者过滤**：「本人 / 我」→ `--author=<git config user.email>`

### 3. 抓取并分类

```bash
git log --since=... --until=... --no-merges --pretty=format:'%h%x09%ci%x09%s' --reverse
```

按 Conventional Commits 的 type 分桶：`feat` → 新增功能；`fix` → 修复 bug；其他（chore/refactor/docs/test/perf/build）→ 版本与发布段。先用 `wc -l` 给出总数与分布，作为输出的开篇元信息。

### 4. 按主题归并（关键步骤）

**禁止逐条罗列 commit。** 相关 commit 合并到一个主题条目，每个主题一句概括性表述，技术细节（接口名/字段名/组件名）放括号或补充行。

主题数量参考：feat ≤ 8 个主题段（每段 ≤ 10 项）；fix ≤ 8 个主题段（每段 ≤ 12 项）。一条 commit 同属多个主题时，归到**最具体**的那个，不重复列。

### 5. 主题分类参考

按项目实际内容收敛，不硬套。通用参考：

- 核心功能 / 交互流程 / 状态管理
- API / 数据层 / 持久化
- 组件 / UI / 主题 / 视觉
- 性能 / 体验
- 错误处理 / 稳定性
- 工具链 / 构建 / 多语言

### 6. 输出格式

```
开篇一行总览：HEAD 状态 + 时间范围 + commit 总数 + feat/fix/其他 分布

## 一、新增功能（feat）
### <主题1>
1. **<主题主标题>**：<内容描述>（必要时附技术细节）

## 二、修复 bug（fix）
### <主题1>
1. **[issue-key]** <issue 摘要>（有 issue 追踪号时编号加粗放最前）

## 三、版本与发布
- **<package>**：<old> → <new>
- 关联工具链改动
```

小范围（≤10 条）可省略主题分段，直接展平为编号清单。

### 7. 行级格式规则

- 每条 1~2 行，**先动作、后细节**
- 主标题用 `**bold**`，结尾不加句号
- 多个相关 commit 合并为一项时用「、」「+」分隔细节
- 优先用项目已有词汇
- **禁止** commit hash 出现在描述里
- **禁止**「修复了…」「添加了…」完成时——用祈使句「修复…」「新增…」
- **禁止**把每条 commit 翻译成自然语言（那是搬运，不是整理）

## 严格规则（DO / DON'T）

**DO**

- 同步最新代码再汇总
- 主题概括 + 技术细节双层结构
- 跨目录但同主题的 commit 合并到一处单独列段
- 保留 issue 追踪号
- 补「版本与发布」段（如有版本/lockfile/工具链改动）

**DON'T**

- 逐条粘贴 commit message
- chore/refactor 混入主清单第一段
- 列 commit hash
- fix 写成完成时
- 主题段 > 10 项不合并
- 每个 fix 都单列
- 没拉最新代码就直接 git log
